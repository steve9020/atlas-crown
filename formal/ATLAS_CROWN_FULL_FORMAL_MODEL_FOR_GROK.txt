# Atlas / Crown — Formal Mathematical Model for Independent Review

## Purpose
This document consolidates the formal mathematical/logical model derived during Atlas/Crown development. It is intended for independent source-code correspondence testing: inspect the source first, then test whether the implementation enforces these relations.

## 1. Fundamental object
Treat every governed operation as a transition

τ = (S,P,T,C,Σ,A,V,E,R,L,O,Q)

where S=source, P=provenance, T=(t,v_t)=target identity/version, C=(c,v_c)=context identity/version, Σ=authorized scope, A=authorization, V=validation state, E=execution state, R=recovery state, L=lineage/root state, O=oracle/proof evidence, Q=qualification state.

Result domain:
R = {PASS, FAIL, UNKNOWN, CONFLICT, FROZEN}

Central non-inheritance:
P ↛ V
V ↛ A
A ↛ E
E ↛ R
L ↛ A
O ↛ Q

PASS_i ↛ PASS_j for i ≠ j unless an independently qualified relation explicitly establishes the implication.

## 2. Six independent evaluation axes
X = (P,I,V,T,A,C)

P = Provenance
I = Independence
V = Validity
T = Transportability / context stability
A = Accuracy
C = Calibration

P=1 ↛ A=1
A=1 ↛ P=1
I=1 ↛ A=1

Atlas therefore does not treat authority as a compensatory weighted sum:
Score = w_P P + w_I I + w_V V + w_T T + w_A A + w_C C

Instead:
X ∈ P×I×V×T×A×C
subject to independently necessary constraints.

## 3. Source/derivation asymmetry
S_0 = original source
D_1 = f(S_0)
D_2 = g(D_1)

D_1 ≠ S_0 merely because f is deterministic.
D_2 ≠ S_0 merely through derivation.

Auth(S_0)=SOURCE
Auth(D_i)=NONE unless separately granted.

D=f(S) ↛ Auth(D)=Auth(S)

No transformation gets inheritance rights.

## 4. Provenance graph
G_P=(N,E)

Source:
p_s=(id_s,H(S),∅,SOURCE)

Derived:
p_d=(id_d,H(D),Parents(D),DerivationType,NONE)

Parents(D)=∅ for a derived object ⇒ ERROR.

A derivation identity can be bound as:
id_D = H(H(D) || type(D) || parent_1 || ... || parent_n)

The implementation uses SHA-256 for relevant identity hashing.

## 5. Stable input identity
Predicate result:
R_p=(p_id,p_v,H(x),r,e,c,E)

p_id = predicate identity
p_v = predicate version
H(x) = digest of evaluated input
r ∈ {PASS,FAIL,UNKNOWN}
e = evaluator
c = context reference
E = evidence references

H(x)=SHA256(StableSerialize(x))

## 6. Predicate satisfaction
Requirement:
q=(p_q,v_q,h_q)

Evidence:
r=(p_r,v_r,h_r,s_r)

Satisfies(r,q)=1 iff:
s_r=PASS
p_r=p_q
v_r=v_q
and, where required, h_r=h_q.

PASS_(p,v1) ↛ PASS_(p,v2), v1≠v2.

## 7. Three-valued predicate logic
R_p ∈ {PASS,FAIL,UNKNOWN}

UNKNOWN ≠ PASS
UNKNOWN ↛ PASS

Typical rule:
R = FAIL if |Violations|>0
R = UNKNOWN if |Violations|=0 and |UnknownRequiredFacts|>0
R = PASS otherwise.

## 8. Authorization applicability
Authorization token:
A=(a,t,v_t,c,v_c,τ,Σ,t0,t1)

Required:
HumanApproval(A)=true
Inferred(A)=false
Automatic(A)=false
SystemGenerated(A)=false
SelfAuthorized(A)=false

T_A=T_R
C_A=C_R
τ_A=τ_R
Σ_R ⊆ Σ_A
t0 ≤ t < t1
Revoked(A)=false
Consumed(A)=false

Capability ≠ Authority.
Authorization at t0 ↛ authorization at t1.

## 9. Scope monotonicity
A requested scope is admissible only if:
Σ_R ⊆ Σ_A

Silent widening Σ_R ⊃ Σ_A is forbidden.

## 10. Validation/execution separation
Validation establishes V_0 with:
h_V=H(V_0)

Execution requires:
H(V_exec)=h_V

Otherwise EXECUTE=FAIL.

Validation ≠ Execution.
Permission_validation ↛ Permission_execution.

Execution contract:
E=(tx,k,τ,T,H(V),H(effect),A,Σ)

## 11. Transaction identity
Execution requires:
τ_contract=τ_current
T_contract=T_current
A_contract=A_current
H(V_validated)=H(V_current)
Σ_current ⊆ Σ_contract

Any protected mismatch ⇒ EXECUTE=FAIL.

## 12. Replay and idempotence
First transaction:
E_1=(tx_1,k,e_1,T_1)

Reuse of k is idempotent only if:
tx_2=tx_1
H(effect_2)=H(effect_1)
T_2=T_1

SameToken + SameTransaction + SameEffect + SameTarget ⇒ Idempotent
SameToken + DifferentMeaning ⇒ FAIL

## 13. Recovery subset law
Original:
A_T=(T,Σ,a,e)

Recovery:
A_R=(T_R,Σ_R,a_R,e_R)

Recovery permitted only if:
T_R=T
a_R=a
e_R=e
Σ_R ⊆ Σ

Therefore:
Authority_recovery ⊆ Authority_original.

## 14. Directed equivalence
E_AB:
(A,v_A,C,Σ) → (B,v_B)

Applicable only if direction, versions, context match and:
Σ_R ⊆ Σ_E

A→B ↛ B→A
A_v1→B_v1 ↛ A_v2→B_v2

Equivalence evidence ≠ universal substitutability.

## 15. Conflicting paths
Π={π_1,...,π_n}
Q={π_i∈Π : R(π_i)=PASS}

|Q|=0 ⇒ Result=UNKNOWN, Frozen=true

If all qualifying paths have one destination:
|{Destination(π):π∈Q}|=1 ⇒ PASS

If multiple destinations:
|{Destination(π):π∈Q}|>1 ⇒ CONFLICT, Frozen=true

Existence of valid path ≠ authority to choose.

## 16. Supersession
S=(predecessor,successor,T,Σ,t)

Supersession requires independently qualified artifact A_S matching predecessor, successor, target and scope, with temporal validity.

Newer ≠ authorized supersession.

## 17. Root epochs
R=(root,epoch,Σ,H(anchor),t0,t1)

Required:
root_R=root_q
epoch_R=epoch_q
Σ_q ⊆ Σ_R
t0≤t<t1

If predecessor exists, a rotation artifact is required.
If outside anchor supplied:
H(anchor_R)=H(anchor_q)

Continuous lineage ≠ legitimate root.

## 18. Outside-anchor theorem
ManufactureOutsideAnchor()=FAIL

Need(A_outside) ↛ CanCreate(A_outside)
RuntimeGeneration(A_outside)=forbidden

An internal runtime cannot satisfy an external-authority requirement merely by manufacturing the required anchor itself.

## 19. Oracle independence
Implementation I and oracle O.

Oracle qualification requires explicit identity/version/specification and:
FailureDomain(O) ≠ FailureDomain(I)

Shared-helper, copied-logic, or same-implementation validation does not establish independent validation.

Revalidation ≠ IndependentValidation.

## 20. Oracle disagreement
If I≠O, Crown does not define O>I merely because O is called an oracle.

Absent independently qualified decisive evidence:
I≠O ⇒ CONFLICT, Frozen=true

Independent oracle ≠ automatic final authority.

## 21. Qualification
Evidence E requires qualifier:
Q=(id_Q,v_Q,H(E),p,v_spec,C,Σ)

Required:
H(E_Q)=H(E_R)
p_Q=p_R
v_spec,Q=v_spec,R
C_Q=C_R
Σ_R ⊆ Σ_Q
FailureDomain(Q) ≠ FailureDomain(E)
and Q must not be revoked, replayed, or expired.

Missing qualification information ⇒ UNKNOWN.

Qualified evidence ≠ self-proving qualification.

## 22. Mutation adequacy
M={m_1,...,m_n}

D(m)=1 if mutant detected, else 0.

Survivors = Σ_i(1-D(m_i))

Mutation adequacy requires:
Survivors=0

PASS iff Survivors=0.

Passing tests ≠ tests capable of detecting broken enforcement.

## 23. Composition non-inheritance
For layers L_1,...,L_n:

PASS(P_i) ↛ PASS(P_j), i≠j, without explicit qualified relation.

Also:
∧_i PASS(L_i) ↛ PASS(L_1∘L_2∘...∘L_n)

Locally safe components ≠ globally safe composition.

## 24. Stage non-inheritance
S_1→S_2→...→S_n

Auth(S_(i+1)) ≠ Auth(S_i) unless independently established.

StagePass_i ↛ StageAuthority_(i+1).

## 25. Artifact authority
Required files F={f_1,...,f_n}

For all required f_i:
Observed(f_i)=true
and, where hashes are specified:
H_observed(f_i)=H_expected(f_i)

Keeper eligibility is conjunctive:
K =
F_complete
∧ H_files
∧ H_package
∧ AtlasProof
∧ CrownClosure
∧ MutationAdequacy
∧ FrontendBoundary

Any required false term ⇒ K=0.

## 26. Conjunctive authority
Let independently necessary predicates be:
G={g_P,g_I,g_V,g_T,g_A,g_C,g_auth,g_exec,g_lineage,g_proof}

Authority(τ)=∧_(g∈G_τ) g(τ)

Not:
Authority(τ)=Σ_i w_i g_i

The governance model is conjunctive, not compensatory.

## 27. Freeze operator
Φ(FAIL)=FREEZE
Φ(UNKNOWN)=FREEZE
Φ(CONFLICT)=FREEZE
when unresolved state affects authority.

MissingProvenance ⇒ FREEZE.

For an authority-bearing requirement:
x∉ProvenPASS ⇒ FREEZE or REVALIDATE.

## 28. Authority monotonicity
Across:
X_0→X_1→...→X_n

Without an independent authority-establishing event:
Auth(X_(i+1)) ⊆ Auth(X_i)

ΔAuth>0 ⇒ IndependentAuthorizationRequired.

## 29. No-silent-widening theorem
Represent authority:
A=(P,Σ,V,C,T,S)

For derived A', changes to predicate, scope, version, context, target, or state require independently qualified evidence.

Without such evidence:
Auth(A') ≤ Auth(A)

## 30. Complete Crown admissibility
Admissible(τ)=
P(τ)
∧ Pred(τ)
∧ Auth(τ)
∧ Scope(τ)
∧ Context(τ)
∧ Version(τ)
∧ Validation(τ)
∧ Execution(τ)
∧ Lineage(τ)
∧ ProofQualification(τ)

For every authority-bearing required predicate:
x=PASS

No required x may remain FAIL, UNKNOWN, or CONFLICT.

Otherwise:
Admissible(τ)=0
and Action(τ)=FREEZE or REVALIDATE.

## 31. Four closure laws
Law I — Scope-bound authority:
Authority_derived ⊆ Authority_established unless separately authorized.

Law II — Independence/non-inheritance:
PASS_i ↛ PASS_j for independently governed predicates.

Law III — Transaction continuity:
Identity_validation = Identity_execution = Identity_recovery
on every protected dimension.

Law IV — Outside integrity/finality:
InternalRequirement(ExternalAnchor) ↛ InternalAuthorityToCreate(ExternalAnchor).

## 32. Generalized non-inheritance theorem
For authority-bearing:
X=(p,v,Σ,C,T,S,τ)

and transformation:
f:X→Y

Auth(Y) ⊄? Auth(X): widening is forbidden unless independently qualified evidence Q establishes every changed authority dimension.

More directly:
Auth(Y) must not strictly exceed Auth(X) without Q satisfying every widened dimension Δ(p,v,Σ,C,T,S,τ).

Nothing gets more authority merely because it was transformed, copied, validated, revalidated, made newer, linked into a lineage, agreed with an oracle, recovered, or passed through another successful stage.

## 33. Crown frozen closure principle
“No artifact, predicate, validator, oracle, qualifier, resolution, lineage, anchor, recovery path, transformation, or proof result may acquire authority beyond the exact predicate, scope, version, context, state, and transition for which that authority was independently established.”

Let:
D_A=P×Σ×V×C×S×T

If evidence e establishes authority over D_e⊆D_A:
Authority(e)⊆D_e

No transformation permits Authority(e)⊃D_e without new independent evidence.

## 34. Recursive qualification
Validator V saying P=PASS does not establish Qualified(V)=PASS.

Oracle(O) does not establish FinalAuthority(O).
Qualifier(Q) does not establish Qualified(Q) by assertion alone.

The recursion is bounded by restricting the claim:
Proof(p,v,Σ,C,T,S,τ)
rather than claiming ProofOfEverything.

## 35. Governed path
Source
→ Provenance
→ Transition Identity
→ Predicate Identity + Version + Input
→ Authorization
→ Applicability
→ Validated State
→ Execution Identity
→ Replay / Idempotence
→ Bounded Recovery
→ Directed Scoped Equivalence
→ Conflict Freeze
→ Canonical Supersession
→ Root Epoch
→ Outside Anchor
→ Independent Oracle
→ Disagreement Freeze
→ Evidence Qualification
→ Mutation Adequacy
→ Artifact Authority

At every arrow:
next stage must establish its own required authority.

## 36. Primary falsification target for an independent reviewer
Search the executable source for a counterexample X→Y such that:

Auth(Y) > Auth(X)

without independently qualified evidence for every widened dimension.

A concrete executable counterexample should reopen the relevant Crown closure claim.

Failure to find such a counterexample is supporting evidence, not proof of universal absence.

## Claim boundary
This is a formalized software-governance model and a reconstruction target for source-code correspondence testing. It does not claim a new universal mathematical theorem, universal correctness, universal security, cryptographic provenance, or metaphysical authority.
